PRIMARY DOCUMENTATION AND LIMITATIONS
1. Apple says macOS Mojave 10.14 was the final release that runs 32-bit apps;
   macOS Catalina 10.15 and later do not support them. Consequently an i386-only
   Mach-O cannot be loaded unchanged in the normal modern macOS plug-in path.
   https://support.apple.com/en-us/103076
2. Rosetta translates x86_64 applications and applies to the entire process;
   arm64 and x86_64 cannot be mixed inside one process. This is not a native
   arm64 conversion service for an old i386 plug-in.
   https://developer.apple.com/documentation/Apple-Silicon/about-the-rosetta-translation-environment
3. Apple requires modern Audio Component or Audio Unit Extension APIs for new
   arm64/macOS 11+ SDK audio-unit code; Carbon Component Manager cannot be used
   for that architecture. Recovered Carbon GUI/registration code must be replaced.
   https://developer.apple.com/documentation/apple-silicon/porting-your-audio-code-to-apple-silicon
4. JUCE's own tutorial states recent JUCE packages include files needed for
   VST3 and AU builds. Local header inspection substantiates this here.
   https://juce.com/tutorials/tutorial_create_projucer_basic_plugin/
5. Current VST3 SDK documentation supports Apple Silicon and Xcode/CMake;
   current SDK 3.8.x uses MIT licensing. That does not retroactively establish
   the license of the installed older JUCE-bundled VST3 3.7.2 headers.
   https://github.com/steinbergmedia/vst3sdk/blob/master/README.md
6. Steinberg's published VST2 position: SDK distribution and new license
   agreements ended in October 2018; its current portal says distribution
   under its VST2 SDK requires the earlier signed agreement. This is a concrete
   dependency/distribution consideration for a conventional SDK-based build,
   not an assertion that personal reverse engineering or independent ABI
   implementation is categorically prohibited.
   https://forums.steinberg.net/t/vst-2-sdk-discontinued/201774
   https://steinbergmedia.github.io/vst3_dev_portal/pages/VST%2B3%2BLicensing/Which%2Bfiles%2Bfall%2Bunder%2Bwhich%2Blicense.html
7. Native format support is host-specific: Steinberg documents that native
   Apple Silicon Cubase/Nuendo accepts VST3 only. A future arm64 .vst would
   therefore not guarantee compatibility with every native host.
   https://helpcenter.steinberg.de/hc/en-us/articles/32056309094290-Cubase-Nuendo-Using-the-native-Apple-Silicon-version
